# 农业种植 IoT 大屏前端 MVP 方案

## 1. 项目概述
- **目标**：构建一套用于农场种植场景的可配置大屏展示页面，实时呈现作物生长环境、农事活动与设备状态等关键数据。
- **角色**：
  - **展示端**：面向访客与管理者的只读大屏。
  - **配置后台**：由具备权限的运维人员配置模块显示与排序。
- **设计原则**：
  - MVP 范围，突出“必需可见”信息。
  - 模块化、低耦合，可按需拓展。
  - 5 秒内掌握全局，信息分层清晰。

## 2. 模块清单与默认状态
| 模块 | 描述 | 默认状态 | 可配置项 |
| --- | --- | --- | --- |
| 顶部总览 KPI | 今日/本周作物面积、在线设备数、未处理告警、今日用水量 | 必选，始终展示 | 仅排序 |
| 地图/农田分区格网 | 农田区块状态可视化，点击查看区块温湿度与墒情 | 必选，始终展示 | 仅排序 |
| 环境监测 | 气温、湿度、光照、降雨量、土壤温度/湿度、电导率 | 默认开启 | 显示开关、排序 |
| 作物生长监测 | 长势指数状态色块、病虫害告警列表 | 默认开启 | 显示开关、排序 |
| 农事活动面板 | 今日/本周农事任务（标题+状态） | 默认关闭 | 显示开关、排序 |
| 灌溉与用水 | 今日用水量、灌溉执行次数、设备在线率 | 默认开启 | 显示开关、排序 |
| 设备状态 | 设备分类统计、异常/离线 TOP10 | 默认开启 | 显示开关、排序 |

## 3. 布局建议
1. **栅格布局**：整体采用 24 栅格，支持 1920×1080 全高清。
2. **顶部区域**：
   - 第一行固定放置“顶部总览 KPI”。
   - 第二行放置“地图/农田分区格网”，占据中心宽度，保证可视化效果。
3. **下方模块区**：
   - 以卡片形式呈现，可按后台排序由上到下、由左到右排列。
   - 支持 1×1、2×1 等不同尺寸，以适配数据密度。
4. **视觉风格**：深色背景+亮色对比，重点信息采用高饱和配色；状态色统一（正常=蓝/绿，关注=黄，异常=红）。

## 4. 数据结构与接口
```jsonc
{
  "modules": [
    { "id": "kpi", "type": "kpi", "enabled": true, "order": 1, "payload": { ... } },
    { "id": "map", "type": "map", "enabled": true, "order": 2, "payload": { ... } },
    { "id": "env", "type": "environment", "enabled": true, "order": 3, "payload": { ... } }
    // ... 其它模块
  ]
}
```
- **modules**：后台配置返回的模块数组。
- **enabled**：勾选状态；前端仅渲染 `true` 的模块。
- **order**：排序权重；前端排序后渲染。
- **payload**：模块所需的数据对象，可按模块类型定义字段。

### 必选模块数据示例
- **KPI**
  ```jsonc
  {
    "kpi": {
      "area_ha": 235.6,
      "online_devices": 128,
      "pending_alarms": 4,
      "water_usage_today_m3": 86.3,
      "water_usage_week_m3": 512.7
    }
  }
  ```
- **地图/农田分区**
  ```jsonc
  {
    "map": {
      "zones": [
        {
          "id": "zone_a1",
          "name": "A1 区",
          "status": "normal",
          "metrics": {"temp": 24.5, "humidity": 68, "soil_moisture": 24}
        }
      ]
    }
  }
  ```

## 5. 前端实现建议
- **框架**：React + TypeScript + Vite，结合 Ant Design Charts/ECharts 实现可视化。
- **状态管理**：使用 Zustand 或 Redux Toolkit 管理模块配置与实时数据。
- **组件设计**：
  - `ModuleRenderer`：接收模块数组，负责排序和渲染。
  - `ModuleCard`：包裹每个模块的通用外观。
  - 各业务模块组件：如 `KpiModule`、`MapModule`、`EnvironmentModule` 等。
- **数据更新**：
  - 通过 WebSocket 或定时轮询获取实时数据。
  - 提供“数据更新时间”显示，提升透明度。
- **响应式**：大屏场景主要针对 16:9，但保留基本的窗口自适应能力。

## 6. 配置后台交互流程
1. 运维在后台选择需要展示的模块并设置排序号。
2. 后台保存后，向前端暴露 `GET /dashboard-config` API。
3. 展示端在初始化时请求该配置，并根据 `enabled` 与 `order` 渲染。
4. 数据接口（如 `GET /realtime-data`）按模块类型返回对应的 payload。
5. 支持通过 WebSocket 推送告警、设备状态等即时信息。

## 7. 验收用例对应实现
- **模块勾选**：`enabled=false` 的模块在前端不渲染，对应用例 1。
- **模块排序**：根据 `order` 排序后渲染，对应用例 2。
- **必选模块保护**：`kpi`、`map` 在前端强制 `enabled=true`，忽略后台关闭请求，对应用例 3。
- **全关时展示**：模块渲染逻辑回退到只剩必选模块，对应用例 4。
- **权限隔离**：展示端仅使用 `GET` 接口，不暴露修改能力，对应用例 5。

## 8. 技术迭代路线
- **阶段 1**：实现固定模块（KPI、地图、环境、设备、告警），使用静态配置。
- **阶段 2**：接入后台配置接口，实现模块勾选与排序。
- **阶段 3**：拓展作物生长、农事活动、视频监控、气象等高级模块，优化可视化效果。

## 9. 非功能性要求
- **性能**：模块渲染在 1 秒内完成；数据更新动画流畅。
- **稳定性**：断网时提示“数据连接中断”，并提供最近更新时间。
- **可运维性**：日志记录模块加载和数据请求结果，便于排障。

## 10. 后续扩展方向
- 引入多屏联动、分辨率自适应配置。
- 与农机调度系统对接，实现任务联动。
- 引入 AI 识别结果（病虫害图像识别、产量预测模型）。
